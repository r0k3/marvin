# CLAUDE.md

Marvin: long-term memory for AI agents, stored as Markdown under Git. This repo is both a product (`marvin-memory` on PyPI, `marvin` CLI/MCP server, Claude Code plugin) and the reference implementation of the K-Lines paper (SSRN 6234218). Read `ARCHITECTURE.md` before structural changes.

## Commands

```bash
uv run pytest -q                     # full public suite (~360 tests, no network, seconds)
just lint / just fmt                 # ruff check / format (pre-commit runs both)
uv run pytest experiments/tests experiments/consolidation   # research-side suites
just sync-plugin                     # copy canonical skill into the plugin (see rules)
just changelog v0.X.Y                # regenerate CHANGELOG.md via git-cliff
uv run python -m marvin.eval.demo    # bundled retrieval demo
uv run marvin <cmd>                  # run the CLI from source
uv tool install --force --reinstall '.[consolidate]'   # refresh the global dogfood install
```

Dev sync: `uv sync --dev --extra consolidate --extra cluster --extra gpu`.

## Layout

- `src/marvin/` — the package. `service.py` is the operation surface; `cli.py` (AXI/TOON CLI + hook commands), `server.py` (20 MCP tools, FastMCP), `index.py` (FTS5 + sqlite-vec + entity-graph RRF), `vault.py`/`models.py` (Markdown storage, structured facts), `consolidation.py`/`extraction.py` (sleep pass, LLM), `bus.py` (in-process default, NATS behind `[cluster]`), `promotion.py` (correction detector), `sanitize.py`, `project.py`, `export.py`, `klines.py` (templates), `skill/SKILL.md` (canonical agent skill).
- `plugins/marvin-memory/` — the Claude Code plugin; the repo root `.claude-plugin/marketplace.json` makes this repo a marketplace.
- `tests/` — public suite. `docs/` — mkdocs site. `examples/demo_vault/` — demo data.
- `experiments/` — **gitignored research code and results. Never commit anything from it.** The public repo is the solution and benchmark harness only. Research roadmap and status live in `experiments/PRODUCTIONIZE.md` and `experiments/STATUS.md`.

## Hard rules

1. **Zero LLM calls on the write and query paths.** This is the product's core claim. LLMs run only in the sleep pass (`consolidation.py`, `extraction.py`) and the eval reader/judge. Do not add LLM calls, network calls, or blocking model loads anywhere else.
2. **Import cost is a feature.** The CLI runs in per-prompt hooks (~0.4 s budget). litellm, langextract, and the mcp server stack are lazily imported; keep it that way. New heavy dependencies go behind an extra with a guarded import (`_extras.require` pattern) so the base install stays retrieval-only.
3. **The vault is the source of truth and the work queue.** Derived state (the SQLite index) must always be rebuildable from Markdown. Pending work is tracked with frontmatter flags (`consolidated`, `extracted`), never in a separate store that can drift.
4. **Hooks always exit 0.** `marvin hook ...` must never break a host session: catch everything, write errors to stderr, print nothing on failure.
5. **Sanitization policy is asymmetric by design.** Invisible-Unicode stripping applies to every write; injection scanning applies only to sleep-pass LLM output. Never content-filter user- or agent-authored notes (a note about prompt injection must be storable).
6. **Facts are never overwritten or deleted.** Same concept + predicate with a new value soft-deprecates the old fact (`deprecated_reason`, `replaced_by`). Preserve this in any storage change.
7. **The canonical skill lives at `src/marvin/skill/SKILL.md`.** The plugin's copy must be byte-identical (test-enforced); after editing, run `just sync-plugin`. Skill edits follow the skill-TDD protocol used to build it: pressure-test against baseline agent behavior, don't just wordsmith.
8. **`docs/architecture.md` is a copy of `ARCHITECTURE.md`.** After editing the root file, `cp ARCHITECTURE.md docs/architecture.md`.
9. **Version lives in `pyproject.toml` and `plugins/marvin-memory/.claude-plugin/plugin.json`** and must match (test-enforced). The distribution is `marvin-memory` (PyPI name `marvin` is taken); the import package and console script stay `marvin`.
10. **Conventional commits.** `feat:`/`fix:`/`docs:`/`chore:` etc.; CHANGELOG.md is generated by git-cliff, never edited by hand.

## Testing conventions

Tests use the deterministic hash embedder (`embedding_provider="hash"`) and temp vaults; nothing touches the network or downloads models. `tests/conftest.py` pins `MARVIN_AUTO_PROJECT_TAG=false` so the repo's own project tag can't leak into assertions; dedicated tests re-enable it explicitly. CLI tests drive `cli.main(argv)` and assert on TOON output and exit codes (0 ok, 1 runtime error, 2 usage; hooks are the exception per rule 4).

Host-integration claims (hook stdout injection, env propagation) are verified empirically against real binaries, not documentation: seed an unguessable fact, disable tool use, require the host to answer it. Grok ≤ 0.2.118 executes hooks but discards their stdout; that finding and method are the bar for adding a new host to the support matrix.

## CLI conventions (AXI)

New commands follow the existing TOON output contract: declared-count tables (`hits[3]{title,kind,path}:`), definitive empty states, a `help[]` block of concrete next-step commands, structured `error[1]{code,message}` on stdout with exit 1. Bare `marvin` is a dashboard, not help text. Keep default schemas minimal; add `--fields` for more.
